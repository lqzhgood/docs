# 黑客松 —— 健康陪伴网关 ByteBuddy

> 将散落在多个硬件中的沉默健康数据，重塑为一份「懂你、提醒你、关心你」的专属解读，并通过桌面机器人以**有温度的方式**送达。

---

![cover](./cover.png)

## 1️⃣ 一句话定位

**为多硬件健康用户打造的「数据中枢 + LLM 解读 + StackChan 桌面机器人」一体化健康关怀网关。**

## 2️⃣ 核心问题与价值

### 真问题

现代人手腕上戴着手环、脚下踩着体脂秤、桌上摆着血压计……硬件越堆越多，但用户依然回答不出「我到底健不健康」这个最朴素的问题。三个真实断层：

1. **数据脱离语义** —— 屏幕上是「步数 8732 / 心率 72 / SpO2 98」，没人告诉你这些数字组合在一起意味着什么。
2. **生态孤岛** —— 手环数据锁在 A 厂商 App、体脂秤数据锁在 B 厂商小程序，没有任何中心节点能拼出完整画像。
3. **解读链路断裂** —— 体检准确但滞后；用户主诉及时但模糊；硬件数据本该是「既及时又客观」的最佳信号源，却沦为吃灰的电子面板。

### 灵感来源

团队成员中既有**异地关怀父母的子女**，也有**戴着手环却不知道数据意味着什么的高负荷脑力工作者**。我们发现：真正稀缺的不是「再多一块表」，而是一个**能跨设备、跨协议汇聚数据，并用人话主动告诉我「现在要不要担心」的中枢**。

### 我们为谁解决

| 典型画像               | 在本作品中获得的价值                                                |
| ---------------------- | ------------------------------------------------------------------- |
| **健身与体重管理人群** | 心率 + SpO2 + 运动姿态 + 过载系数联合解读，运动后获得拟人化正向反馈 |
| **高负荷脑力工作者**   | 久坐 90 分钟后机器人主动提醒；心率异常时第一时间感知                |
| **异地关怀父母的子女** | 远程触达——当父母端 StackChan 检测到异常，可联动家庭消息穿透到子女   |
| **慢病人群**           | 1Hz 连续监测 + 规则引擎双重冷却，避免漏报也避免疲劳告警             |

### 价值类型

- **功能性价值**：跨品牌数据融通 + LLM 综合解读，把「看图」升级为「听结论」。
- **情绪价值**：StackChan 通过**舵机动作 + 屏幕表情 + 语音 TTS** 三模态反馈，把机械告警转成「有温度的陪伴」。这是手机推送做不到的体验。

### 核心场景演示

#### 场景 1：工位归位主动问候（含「八卦式」数据解读）

用户走进工位 → BLE 网关持续扫描手环 MAC，RSSI 越过「入座阈值」并稳定 ≥ 15s →
判定为**归位事件** → Platform `family_message` 优先级的轻量分支拉起 →
LLM 拉取**今晨 6:00 至当前**的心率/SpO2/步数时序，与用户 7 日同时段基线对比 → 生成**拟人化、带梗的开场白**，由 StackChan 主动转头 + 挥手表情 + 语音播报：

- 基线内：「早呀，今天看起来神清气爽，咖啡要不要安排上？」
- **心率显著高于基线**（如今晨峰值 120 bpm vs 基线 78 bpm，且非运动场景）：「嚯——今早心跳飙到 120，是路上跑起来了，还是……遇见谁了？😏」
- 步数异常多 + 心率平稳：「你今天上班路上多走了 1200 步，是地铁又坏了，还是想多看一眼那个谁？」
- SpO2 偏低 + 心率偏高：「看起来昨晚没睡好哦，要不要我帮你点一杯美式？」

**亮点**：把冷冰冰的「晨间健康摘要」做成**有梗、有温度、像同事/朋友打招呼**的开场，既完成了健康播报，也建立了机器人的人格记忆点——这是手机推送永远做不到的体验。

#### 场景 2：久坐熔断 × 「假装离座」识别

连续 90 分钟低活动量 → 规则触发（rule cooldown 30 min，action cooldown 60 min）→
机器人头部 yaw 转向用户、LED 切橙色高亮 → 语音播报「站起来走走，喝口水」。

**真实离座校验闭环**：考虑到大量用户会因为手头工作「嗯一声就跳过」，提醒之后并不会真的起身，我们引入**摄像头 + 蓝牙 RSSI 双信号融合**的离座判定：

1. **触达后进入 5 分钟观察窗口**：StackChan 本地摄像头持续做人形/人脸在位检测（轻量 MobileNet 推理），同时 BLE 网关实时采样手环 RSSI 与 IMU 步数增量。
2. **三种判定结果**：
    - ✅ **真实离座**：摄像头连续 ≥ 30s 未检测到人，且手环 RSSI 衰减超过阈值（远离桌面），且步数有持续增量 → 触发拟人化正向反馈（机器人鼓掌表情 + 语音「干得漂亮，回来再战」），并把当前规则的 cooldown **延长到 90 min**。
    - ⚠️ **假装离座**：摄像头判定离开但 RSSI 未衰减（人没动，只是低头/侧身），或 RSSI 衰减但步数为 0（仅把手环放远） → 机器人语气升级为「我看到你只是把手机推远了哦，真的站起来走两步嘛」，并把后续提醒**频率提高一档**（cooldown 30 min → 10 min）。
    - ❌ **完全无响应**：5 分钟窗口结束仍在位 → 提升场景优先级（80 → 85），LED 切红色脉冲，语音加重「再坐下去腰真的要废了」，并将该用户当日的久坐基线**整体收紧 20%**（下次触发阈值由 90 min 降至 72 min）。
3. **隐私优先**：摄像头推理**完全在 StackChan 端侧完成**，不上传任何图像帧，仅回传布尔在位信号到 `server-data`。

#### 场景 3：运动后正向激励（含运动类型识别 + 仪式感关 session）

跑步/骑行/力量训练归来 → M5StickC Plus IMU 检测到「持续高频抖动 + 心率高位 → 心率快速回落」的典型运动收尾曲线 → 自动**关闭运动 session** 并触发 `server-data` 规则匹配 → Platform `health` 场景拉起 → LLM 多维度生成评语：

1. **运动类型自动识别**：基于 IMU 时序特征 + 心率曲线形态做轻量分类（跑步 / 骑行 / 有氧 / 力量 / HIIT），无需用户手动开启 session。
2. **多维数据融合**：本次 session 的**最大心率 / 平均心率 / HRV 恢复速率 / 燃脂时长 / 步频或踏频**与用户 **7 日同类型运动基线**对比，并叠加**今日睡眠/疲劳分**做强度合理性判断。
3. **三档拟人化反馈**：
    - 🏆 **突破个人最佳**（如 5km 配速比 7 日均值快 ≥ 8%）：「PB 啦！这速度去当配速员都够格了，奖励你解锁『火箭头转』限定动作」+ 触发 `/expression/rocket` 编排动画。
    - ✅ **状态在线**（HRV 恢复速率优于基线）：「今天心跳恢复得很棒，看起来状态在线，明天可以加一点强度」+ 触发 `/expression/cute` 编排动画。
    - ⚠️ **过度训练预警**（连续 3 天高强度 + HRV 持续下降）：「最近练得有点猛，今晚早点睡，明天给身体放个假吧」+ LED 切暖黄、机器人低头表情。

**亮点**：把「关闭运动 session」做成**带仪式感的解锁瞬间** —— 像游戏通关动画一样反馈给用户，让一次普通跑步从「数据条」升级为「值得回味的事件」。

#### 场景 4：清晨状态初始化（多源融合的「今日简报」）

早晨**踏上体脂秤**或**起床心率**被采集 → `server-data` 触发 `morning_briefing` 规则 →
Platform 拉起轻量 `health` 分支 → 在 ≤ 3s 内完成**多源数据融合**：

| 数据源       | 用途                                       |
| ------------ | ------------------------------------------ |
| 体脂秤       | 体重 / 体脂率 / 7 日趋势                   |
| 手环睡眠监测 | 总时长 / 深睡比 / REM / 入睡延迟           |
| 起床心率     | 静息心率与 30 日基线对比，体现自主神经状态 |
| 室温 / 湿度  | 影响着装建议                               |
| 天气 API     | 今日温差、降水概率                         |

LLM 综合上述输入生成**「轻量化今日简报」**，由 StackChan 屏幕气泡 + 语音播报：

- 😴 **睡眠优秀 + 体重稳定**：「昨晚深睡 1h45min，状态满格，今天可以挑硬骨头啦」+ 推荐高蛋白早餐。
- 😵 **深睡不足 + 静息心率偏高**：「深睡不足 30 分钟，自主神经看起来还没回来，今天别排太满，午饭建议清淡 + 补一杯电解质水」。
- 📈 **体重连续上涨**（≥ 3 天小幅上涨）：「连续三天上涨啦，要不要把今天午餐换成轻食？我也帮你把晚上的久坐提醒收紧一点」。
- 🌧 **天气联动**：「外面 12 度还有雨，外套别忘了，伞挂在门口那个钩子上哈」（如已绑定家居位置标签）。

**亮点**：简报**不是固定模板**，而是基于**昨夜睡眠 × 今日体重 × 自主神经状态 × 外部天气**的动态合成，做到「每天都不一样、每天都精准」。

#### 场景 5：异常事件统一告警（血氧 / 跌倒 / 心率骤变 / 长时倒地 → 多端家人推送）

把所有「需要立刻被注意到」的事件 —— **低血氧、跌倒、心率骤变、晕厥后长时倒地** —— 收敛到**一条统一的异常事件总线**，由 `server-data` 的规则引擎统一识别，由 Platform 统一编排响应、由 `family_message` 统一向家人多端穿透。

**一、统一异常事件识别**

| 异常类型    | 检测信号源                                  | 触发条件                                                      |
| ----------- | ------------------------------------------- | ------------------------------------------------------------- |
| 🩸 低血氧   | M5StickC Plus 1Hz SpO2                      | SpO2 持续低于阈值（92 / 90 / 85 分级）                        |
| 🤸 跌倒     | M5 内置 6 轴 IMU 过载系数 G + 姿态突变      | G ≥ 2.5G 且 0.3s 内姿态由 STILL/WALK 突变为 LIE               |
| 💓 心率骤变 | 手环 HR 一阶差分                            | 静止状态下 5s 内 HR 上升 ≥ 40 bpm 或下降 ≥ 30 bpm             |
| 🛌 长时倒地 | IMU 姿态 = LIE 持续 + 步数零增量 + 心率仍在 | LIE 状态持续 ≥ 60s 且步数无增长（区分「主动躺下」与「晕厥」） |
| 🌡 体温异常 | 体温模块（可选）                            | 持续 ≥ 38.5°C 或低于 35°C                                     |

**二、双重假阳性过滤**（避免狼来了）

- **传感器漂移过滤**：SpO2 单点暴跌 + 同时序 HR 完全平稳 → 判定传感器漂移、丢弃；指夹/手环剧烈晃动时不触发告警。
- **行为合理性过滤**：检测到「跌倒姿态」但**前 2s 内有 IMU 主动放置特征**（如缓慢平放手腕）→ 判定为**主动躺下**，不升级；用户**主动按下机器人取消键** 5s 内 → 取消本次告警。

**三、跌倒/晕厥的「主动询问 → 升级」闭环**

跌倒事件触发后**不立刻惊动家人**，而是先走**本地核实**：

1. **本地询问（0–15s）**：StackChan 立刻转头朝向用户、LED 闪黄、放大音量喊「我看到你倒下了，能听到我说话吗？拍一下机器人头顶就当我误会啦」。
2. **二次核实（15–60s）**：若用户**没有任何应答**（机器人头顶触摸传感器无触发、语音无回应、IMU 仍处 LIE 静止），机器人触发本地摄像头**拍摄一张现场照片**（端侧人形检测确认人确实倒地后才上传），同时把场景优先级升到 90。
3. **升级到家人（≥ 60s 无应答）**：携带「事件类型 + 时序快照 + 现场照片」一并推送家人，进入下方**多端穿透链路**。

**四、多端穿透：让告警一定打得通**

异常一旦升级为「需家人介入」，**同时**走以下多通道，谁先送达就由谁兜底：

| 通道                         | 用途                                                              |
| ---------------------------- | ----------------------------------------------------------------- |
| 📱 `family_message` App 推送 | 优先级 90，家人 App 强弹窗 + 持续震动直到点击查看回执             |
| 🔔 支付宝服务消息            | 通过支付宝消息能力穿透到家人手机（已绑定亲情号场景）              |
| 📞 紧急联系人语音呼叫        | 10s 倒计时（用户可取消）→ 直接拨打第一紧急联系人                  |
| 💬 微信/短信兜底             | App 推送 2 分钟未读 → 自动转发摘要短信，附现场照片缩略图链接      |
| 🤖 子女端 StackChan 联动     | 若家人也有 StackChan → 子女端机器人**直接抢占场景**、转头播报告警 |

**五、告警全程留痕**

每次异常事件写入 ActionLog，包含：**原始时序窗口**（SpO2/HR/IMU 各 ±30s）、**触发规则 ID**、**升级路径**、**家人回执时间**、**现场照片哈希**。供事后回溯，避免「告警一闪而过、没人记得发生过什么」。

**亮点**：把分散的异常告警**收敛成统一事件总线 + 统一升级模型**；用「**主动询问 → 本地核实 → 多端穿透**」三段式既避免无效打扰、又保证真正危急时**子女端一定收得到**。这是异地关怀父母场景下的**核心兜底能力**。

### 体验入口

## ✨ 附录：技术细节备忘

### Path-prefix 不是鉴权，是混淆

`SERVER_PATH_PREFIX`（如 `/asdfjasjdf`）通过 `app.use(prefix, router)` 单点挂载，未命中前缀的请求 fallback 到 `res.status(404).end()`（空 body，不泄露 header）。这是访问混淆，若需要真鉴权请在 `protectedRouter` 上叠加 token 中间件。

### M5StickC Plus 上踩过的坑

UIFlow `Widgets` 命名空间**没有** `fillRect/drawRect/drawLine`，只能用 `M5.Lcd.*`；`Label.setColor()` 不能调（不同版本签名不一致）；CJK 与 Unicode 颜文字会变方块，必须**纯 ASCII** 且填充到 7 字符固定宽度避免 bounding box 残影；按钮回调是异步的，loop 后段绘图必须二次校验 `start` 状态避免图标残影。这些坑都已在 `stack-c/CLAUDE.md` 沉淀。

### Rust BLE Gateway 的自动重连

每个 HTTP 处理函数在执行 BLE 写入之前都会先调用 `ensure_connected()`，透明完成「检测断连 → 重新扫描 → 重新连接」流程，对调用方完全无感，把 BLE 协议的脆弱性彻底吸收在网关层。

### BLE 与 WS 不能同时常驻，内存会被打爆

ESP32-S3 同时跑 Xiaozhi、BLE、WebSocket remote bridge 时，TLS/AES、MCP tools/list 和音频链路会抢 SRAM，曾出现 esp-aes: Failed to allocate memory 和 network failed。当前 AI Agent 模式保留 BLE，关闭 WS 自动启动；MCP tools/list 分页从 8000 缩到 3000，BLE GATT 也裁到只保留 config 特征，保证 Xiaozhi 回复和 TTS 播放稳定。
