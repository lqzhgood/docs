DevHelper 隐私权政策

本政策说明 Chrome 桌面扩展「DevHelper · 开发助手」（以下简称「本扩展」）会处理哪些数据、这些数据存放在哪里、与谁共享，以及你可以如何删除它们。

生效日期：2026 年 11 月 22 日 最近更新：2026 年 11 月 22 日 适用版本：1.0.23 及之后 适用对象：企业内部研发与测试人员

要点摘要

  • 本扩展是内部研发工具，用于管理 PRE、UAT、PROD 测试账号、共享业务域名环境、采集前后端请求关系，并在企业统一登录页自动完成登录。
  • 账号与密码只保存在你的浏览器本地，不会上传到我们的服务器；只有在你自己点击「分享」「导出」时才会写入剪贴板。
  • 会发送到我们自己服务器的只有：域名环境标注、前端域名与后端请求的对应关系、以及地区与全局配置的读取。上报内容不包含查询参数、请求体、Cookie 或认证头。
  • 使用统计会发送到 Google Analytics，只包含随机安装 ID 和操作/接口元数据，不包含账号、密码、业务域名或请求路径。
  • 我们不出售用户数据，不用于广告，不用于信用评估，也不用于与本扩展功能无关的目的。

1适用范围与身份

本扩展由企业内部的研发团队（以下称「我们」）开发并维护，仅供企业内部研发、测试及相关人员在开发与联调场景中使用。安装、使用本扩展即表示你已阅读并理解本政策。

本扩展会连接由我们运维的项目服务器（地址由部署方配置，可在扩展「高级选项」中修改），用于共享域名环境、地区登录入口、采集过滤规则和前后端请求关系。该服务器不是面向公众的消费类服务。

本政策仅适用于本扩展本身，不适用于你在浏览器中访问的第三方网站（包括企业内部各业务站点与统一登录页）或 Google Analytics。这些服务各自的数据处理规则由其运营方负责。

2单一用途

本扩展的单一用途是：帮助企业内部研发与测试人员在浏览器中管理测试账号、标注并共享业务域名环境、查看前后端请求关系，并在企业统一登录页完成登录或填写账号密码。

本扩展不会用于广告投放、内容推荐、价格比较、浏览行为画像，也不会向与本扩展功能无关的第三方提供数据。

4仅保存在本机的数据

4.1 账号与密码

账号记录保存在 chrome.storage.local，包括登录名、密码、环境、地区、备注和排序信息。账号数据不会上传到我们的服务器，也不会发送给 Google Analytics。

「分享」「导出全部」会把账号 JSON（含明文密码）写入系统剪贴板；账号行上的「复制账号」「复制密码」同样会写入对应字段。写入由你主动触发，之后的内容由你自行选择粘贴到何处。请勿将这类内容粘贴到聊天工具、工单系统或其他非受控渠道。

4.2 连接 IP 与临时标注

扩展会从主文档响应中取得当前页面的实际连接 IP，并结合内置回环规则和远端过滤规则判断页面是否属于本地开发环境。连接 IP 只用于本机判断，不会随请求关系上报。

「临时」环境标注只在本机生效，24 小时后自动恢复，期间不会上报，也不会采集该域名下的请求关系。

4.3 请求记录与缓存

请求关系先在本地去重保存，记录是否已上传与最近使用日期；同步失败时保留本地副本并重试。地区、域名、过滤规则和全局配置的最近一次有效副本同样缓存在本地。

4.4 本地存储的保护与局限

本扩展把本地存储的访问级别限制为受信任上下文，网页内容脚本无法读取扩展存储。但浏览器扩展存储本身不做加密：能够访问该 Chrome 用户配置文件的其他程序或用户，理论上可以读取账号与密码。请为操作系统账户设置密码，不要在共用设备上保存生产环境凭据。

5发送到项目服务器的数据

扩展只调用下列接口，完整前缀为「服务器地址 + /api/chrome-ext-devhelper」：

接口方向内容
GET /config读取刷新周期、本地请求记录上限、统计配置
GET /regions、PATCH /regions读取 / 提交各地区 PRE/UAT/PROD 登录入口与版本；修改由管理员在后台审核
GET /domains、POST /domains读取 / 上报前端主机名、环境（pre/uat/prod）、更新时间戳
GET /domain-blacklist读取采集过滤规则（不含管理员说明）
POST /requests/batch上报每批最多 50 条请求关系

5.1 请求关系的内容

每条关系由「前端主机名 + 请求方法 + 后端 host（含端口）+ pathname」唯一确定，另附最近使用日期。不包含查询参数、请求体、响应体、Cookie、认证头、页面内容，也不包含环境标签与连接 IP。

采集只发生在：顶层页面（不含 iframe）、页面已被明确标注环境、未被标注为临时、且不属于本地/过滤规则的 HTTP 或 HTTPS 的 fetch/XHR 请求。OPTIONS 请求一律不保存、不上报。

5.2 鉴权与传输

业务接口请求使用扩展内置的共享项目 API Key（Authorization: Bearer …）。该 Key 可被扩展使用者提取，属于项目共享凭据，不能用于识别个人。请求不携带浏览器 Cookie，不跟随重定向。

请求头还会携带两个标识：X-DevHelper-Client-Id（随机安装 ID，用于关联同一安装的统计事件）与 X-DevHelper-Request-Id（每次请求独立的随机 ID，用于排查）。这两个值均不包含账号或设备信息。

传输加密：若部署时项目服务器地址使用 http://，请求内容在传输过程中未加密。请通过扩展「高级选项」或部署配置改用 HTTPS，并为自建服务启用 TLS。

5.3 服务器上的数据

服务器按唯一键合并不同成员上报的相同关系，并记录最后一次收到该关系的服务器时间。域名标注以服务器版本为准，过期修改会被拒绝而不是覆盖他人修改。

与所有 Web 服务一样，服务器会在处理请求时获得请求来源 IP、时间与 User-Agent，并写入项目日志供管理员排查故障。日志仅用于运维与安全审计，不与账号关联，也不会出售或用于营销；日志按服务器的运维策略定期清理。

6登录自动化与会话清理

在你于扩展中选择账号并发起登录后，扩展会在当前标签页执行以下本地操作：

  • 清理旧会话：读取当前标签页所属 Cookie 存储中的 Cookie，筛选出对「原业务站点」或「目标统一登录页」生效的条目并删除，同时清除这两个源的 localStorage。Cookie 只在本机匹配与删除，不会被保存或上传。
  • 页面识别：在统一登录页中读取登录页版本与表单结构，确认页面与地区配置一致后才交付账号。
  • 填写与提交：PRE/UAT 会自动填写账号密码并提交；PROD 只填写账号密码后停止，最终登录与验证由你手动完成。凭据提交给统一登录页自身，不经过我们的服务器。
  • 验证步骤：PRE/UAT 下扩展会按页面出现的步骤处理滑块/拼图、可信设备确认和验证码。验证码发送与滑块校验的诊断信息只显示在页面进度面板中，不写入持久存储，也不上报（仅保留百分比、耗时和业务错误码）。

这些自动化只在企业统一登录页（由地区配置限定为受信任的登录域名）和扩展自身的过渡页中运行，不会注入其他网站。

7剪贴板

打开扩展弹窗或侧栏时，扩展会读取一次剪贴板文本，用于识别「单组账号密码」「多组账号」或「DevHelper 导出的账号 JSON」，并提示你是否新增或导入。识别到你确认之前不会保存任何内容；读取失败或无法识别时不做处理。

只有在你主动点击「分享」「复制账号」「复制密码」或「导出全部」时，扩展才会写入剪贴板。这些写入操作可能包含明文密码。剪贴板内容由你控制，不属于我们收集的数据。

8使用统计与第三方

8.1 统计方式

当管理员在项目服务器配置了有效的 GA4 测量 ID 与上报密钥时，扩展会向 Google Analytics Measurement Protocol（https://www.google-analytics.com/mp/collect）发送以下事件：

  • page_view：弹窗、侧栏或设置页被打开，页面地址使用固定虚拟地址（如 https://devhelper.extension/popup）。
  • feature_used：开始登录、标注域名、合并/删除账号、置顶、保存/删除地区、切换服务器等操作，只包含动作名与成功/失败。
  • api_request：调用本项目接口的接口名、方法、HTTP 状态码、耗时、结果类型与请求 ID。

事件使用随机生成的安装 ID（chrome.storage.local 中的 UUID）作为 client_id，不关联你的账号、姓名、邮箱或设备标识。事件参数经白名单过滤，不会发送业务域名、请求路径、账号、密码或页面内容。

未配置有效的测量 ID 与密钥时，扩展不会发送任何统计事件。

8.2 第三方

统计事件由 Google LLC（Google Analytics）处理，可能传输至美国等地区。Google Analytics 的数据保留期由该 GA4 属性的设置决定（通常为 2 个月或 14 个月）。相关处理适用 Google 隐私权政策与Google Analytics 服务条款。

项目服务器也会独立向同一 GA4 属性上报其自身收到的接口请求，用于对比客户端与服务端的调用情况；该服务端上报不含客户端安装 ID 之外的个人信息，也不转发客户端事件。

8.3 被动收集

除上述统计外，扩展不对你的浏览行为做任何分析。

9我们不收集的数据

  • 不收集姓名、身份证件、地址、支付信息或财务信息。
  • 不收集账号密码（账号只保存在本地）。
  • 不上传查询参数、请求体、响应体、Cookie、Authorization 头或网页正文。
  • 不收集精确地理位置；不使用摄像头、麦克风或屏幕录制。
  • 不采集浏览器指纹，不读取系统字体列表或硬件标识。
  • 不读取浏览历史数据库；仅通过标签页 API 读取已打开标签页的地址，用于在工具栏图标上显示环境徽标与识别登录目标页。

10共享、出售与广告

  • 不出售用户数据，也不将数据用于定向广告、再营销或跨站追踪。
  • 除下列情形外，不向第三方披露用户数据：
    • 向 Google Analytics 发送第 8 节所述的匿名统计事件；
    • 向项目服务器（由我们运维）发送域名标注与请求关系，供内部研发共享；
    • 依据法律法规、司法或监管要求必须提供。
  • 共享的域名标注与请求关系不包含个人身份信息，但可能间接反映团队正在开发的业务系统。服务器访问受项目管理员控制。
  • 不使用用户数据判断信用状况，也不用于借贷、保险或就业等用途。

11有限使用声明

本扩展对用户数据的处理遵循 Chrome Web Store 用户数据政策中的 Limited Use（有限使用）要求：

  • 仅将用户数据用于本政策第 2、3 节明确说明的功能；
  • 不出售用户数据，也不为其他目的转让给第三方；
  • 不将用户数据用于或转让给广告平台、数据经纪商或信息转售方；
  • 不使用或转让用户数据来判断信用度，或用于借贷目的；
  • 除为提供或改进本扩展的单一用途所必需外，不向任何人阅读或传输用户数据——本扩展本身不包含人工读取用户数据的功能；
  • 仅在实现上述用途所必需的最小范围内处理数据，并在不需要时删除或匿名化。

12保留期与删除

12.1 本机数据

  • 账号：在扩展中通过账号行的「⋯ → 删除」删除，立即从本地存储移除。
  • 请求记录与域名缓存：「设置 → 高级选项 → 清空本地数据」清除本地请求记录、域名标注缓存、临时标注与未同步标注，然后从服务器重新读取。
  • 本地容量：请求记录默认上限为 5000 条（可在服务器配置为 1 至 1,000,000），达到上限时优先删除已上传且最久未使用的条目。
  • 卸载扩展：在 chrome://extensions 中卸载将删除该扩展的全部本地存储，包括账号。

12.2 服务器数据

服务器保留去重后的域名标注与请求关系，用于团队内查询。如需删除特定主机名或时间范围的数据，请通过第 17 节的方式联系我们，并说明主机名与大致时间范围；我们会在核实后尽快处理。

12.3 统计数据

统计事件按 GA4 属性设置的保留期由 Google 处理。由于统计使用随机安装 ID 且不关联身份，我们通常无法定位特定个人的统计记录；卸载扩展即可停止后续上报。

13安全措施与已知限制

我们采取的措施：

  • 扩展页面与后台之间校验消息来源，只接受来自扩展自身页面与已注册内容脚本的请求；
  • 本地存储访问级别限制为受信任上下文，网页脚本无法读取；
  • 业务接口请求不携带浏览器 Cookie，禁止跟随重定向，设置请求超时；
  • 账号记录带版本标识，写入前校验格式与来源，避免并发覆盖；
  • 地区登录入口只接受受信任的登录域名（HTTPS）；
  • 不加载任何远程代码或远程样式：Inter 字体与全部脚本随安装包分发，不使用 CDN，不动态执行远端脚本。

需要你了解的限制：

  • 本地存储未加密，能访问该 Chrome 用户配置文件的人或程序可以读取账号密码；
  • 内置项目 API Key 可被提取，属于项目共享凭据，不能识别或隔离个人；
  • 若部署使用 HTTP 地址，传输内容可能被同一网络中的他人观察，建议改用 HTTPS。

14权限及用途

host_permissions（所有 HTTP/HTTPS 站点）识别已标注环境的业务站点、清理登录会话、在统一登录页运行登录自动化；无需为每个开发站点单独授权。
webRequest观察顶层页面的请求与连接，获取主文档实际连接 IP，并采集已标注页面发起的 fetch/XHR 请求关系。
webNavigation在页面提交时关联当前文档，判断环境与连接信息是否仍然有效。
tabs、activeTab读取当前标签页地址、切换标签页、在指定标签页发起登录与更新图标徽标。
scripting在统一登录页注册登录自动化脚本，并识别页面版本与表单结构。
cookies切换账号前删除目标业务站点与统一登录页的旧会话 Cookie。
browsingData只清除目标站点的 localStorage，用于重置登录状态。
clipboardRead打开扩展时读取剪贴板，识别可导入的账号。
clipboardWrite分享、复制账号密码与导出全部账号。
storage、unlimitedStorage保存账号、配置缓存与请求关系；避免固定容量配额影响去重记录。
alarms按服务器配置的周期刷新配置与上报请求关系，处理登录超时。
sidePanel在弹窗与侧边栏之间切换。
incognito: split在无痕窗口中独立运行（需用户手动允许）；无痕窗口不生成安装 ID、不发送统计，也不负责同步。

18English Summary

DevHelper is an internal Chrome extension for enterprise developers and testers. It manages test accounts for the PRE/UAT/PROD environments, shares per-host environment labels, records front-end to back-end request relationships, and automates sign-in on the enterprise single sign-on login pages.

  • Stored only on your device: account logins, passwords, environments, regions and notes; connection IPs; temporary environment labels; request records pending upload. Account data is never uploaded. Sharing or exporting copies a JSON document that contains plaintext passwords to your clipboard, initiated only by you.
  • Sent to our project server (address configured at deployment, configurable in the extension): domain environment labels (hostname, environment, timestamp) and request relationships (front-end hostname, HTTP method, back-end host and port, pathname, last-seen date). Query strings, request or response bodies, cookies, authorization headers and page content are never collected or uploaded.
  • Analytics: when configured, anonymous events (random installation UUID, page views, feature usage, API metadata) are sent to Google Analytics. No accounts, passwords, business hostnames or request paths are included. Incognito windows send nothing.
  • Cookies and localStorage: read and deleted locally only, for the target business site and the login origin, to reset login sessions. They are never transmitted.
  • No sale, no advertising, no creditworthiness use, and no processing outside the extension's stated purpose, consistent with the Chrome Web Store User Data Policy (Limited Use).
  • Deletion: delete accounts in the extension, use "Clear local data" for request records and domain caches, or uninstall the extension to remove all local data. Server-side data deletion can be requested by email.
